# Modular snap-together assembly direction

The user's latest motion reference is **Lego-like pieces building up workflows and sub-apps**. Interpret this as an original modular assembly metaphor, not a LEGO-branded toy interface. Keep Flightdeck orange/steel and its readable technical UI.

## Shared visual grammar

1. **Placement ghost.** A quiet outline occupies the real final location of a received node/module. It is a presentation placeholder, not an unresolved model operation or a temporary graph edit.
2. **Piece arrives.** A small decorative faceplate/layer slides into the ghost. Prefer a short vertical approach, slight scale and a restrained snap/settle—not just another opacity fade.
3. **Connection locks.** Accent real typed ports, actual graph connections or supported source/page relationships. Do not invent imports, dependencies, connector authorization or successful data flow.
4. **Whole design.** Show the complete actual artifact, then let the operator step through its explanation, tips and optional narration.

Decorative layers must be pointer-events:none and independent of positioned/editable geometry. Do not transform node wrappers, canvas coordinates, real source editors, interaction targets or saved graph/file data. Existing drag/settings/edit/run actions remain immediately usable and interrupt presentation when needed.

Use the same sequence and restrained snap timing in both builders, with their own real artifacts:

- **Workflow:** registry blocks/wrappers → actual connections → complete DAG → dependency/branch/gate walkthrough.
- **Sub-app:** actual manifest/framework pieces → generated schema/routes → supported page/navigation descriptors → proposed host integration/checks → architecture walkthrough. Omit absent pieces or mark their absence; never manufacture a project structure to fill an animation.

## Controls and honesty

Keep the existing bounded creation replay, grouping for large artifacts, Pause/Resume, Skip and explicit Replay. Reduced motion or Motion off displays the final artifact without travel; manual explanations still work. Ordinary navigation and edits must not silently restart assembly.

The current API returns complete drafts. The assembly is **received-artifact presentation**, not a live model/tool stream or execution trace. It grants no save, deployment, resource activation, human approval or installation authority. Speech remains opt-in and uses the separate scoped native voice provider.

The single chat-first entry is unchanged: no extra assembly/standby dashboard before routing. Assembly starts inside the correct builder after a valid draft and any replacement guard are accepted.

## Ownership and verification

- Workflow refinement: `src/workflow/**`, building on the completed real DAG replay/walkthrough.
- Sub-app refinement: `src/workbench/**`, building on actual candidate files/descriptors.
- Parent: Studio integration, single entry, shared voice scope and combined release.

Require real browser measurements of decorative movement versus stable editing geometry, unchanged exports/history, controlled pause/skip/replay, interruption during actual native drag and reduced/off motion. Capture visible assembly stages from the real component; do not create separate illustrative mock screenshots and present them as runtime evidence.

The refinements are in flight. This document is direction/acceptance criteria, not a claim that the new snap treatment is already verified or deployed.
